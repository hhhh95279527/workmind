# ADR-002：合同风险审查采用「规则引擎 + LangGraph Agent」双轨

- 状态：Accepted（2026-09）
- 相关代码：`server/src/contract/rules/rule.engine.ts`、`rules.seed.ts`、`review/review.agent.ts`、`prisma/schema.prisma`（review_rules.scope: ALL/LABOR）

## 背景

合同风险审查最初设想全部交给 LLM：丢进整份合同，让模型输出风险列表。原型验证发现三个硬伤：

1. **不确定性**：同一条明显违规（如试用期超过法定上限）两次运行结论可能不同，企业场景无法接受；
2. **成本与延迟**：每份合同都全量过模型，演示和批量上传时费用高、等待久；
3. **无 Key 即瘫**：面试演示环境的 API Key 经常是占位状态，纯模型方案在无 Key 时无法展示核心业务。

## 决策

审查管线拆成两条互补轨道，结果合并为统一的风险卡片流：

**规则轨（确定性底座）**

- 规则是 `review_rules` 表中的声明式数据：`code`、severity、scope、`pattern`（正则）、`keywords`（全包含降级）、prompt 模板；
- `runRuleEngine(clauses, rules, {labor})` 纯函数执行：pattern 优先，正则非法/未命中降级为关键词全包含；gm 全量匹配带 200 次 guard 防零宽死循环；
- **scope 分 ALL / LABOR**：劳动类规则（试用期、竞业限制等）只在判定为劳动合同（标题+正文的劳动特征词命中）时启用，避免把劳动条款套到买卖合同上产生误报；
- 正则在规则后台保存前先 `new RegExp` 编译校验，并提供对任意文本的「试运行」。

**Agent 轨（语义增强）**

- LangGraph StateGraph 的 ReAct 循环：模型结合条款上下文、法规库 RAG（legal_search）发现规则未覆盖的隐性风险；
- 无 Key 时发 `agent_skip` 事件跳过，规则轨结果照常返回。

人工终审对两轨风险一视同仁：采纳/忽略/备注，决策持久化并回流为 Eval 样本。

## 后果

正面：

- 已知风险模式 100% 确定性命中、零成本、毫秒级，可解释到具体规则 code；
- 无 Key 环境核心业务完整可演示；
- 规则可由后台非开发人员维护，改规则不必发版。

负面/约束：

- 规则维护需要持续运营（法规更新 → 改规则 → 跑 Eval 回归）；
- 双轨结果需要去重/对齐展示逻辑，复杂度高于单轨。

## 备选方案

- **纯 LLM 审查**：灵活但不确定、贵、强依赖 Key，被否；
- **纯规则**：确定但只能抓字面模式，对「表述隐晦但实质违规」无能为力，故保留 Agent 轨作为语义补充而非替代。
